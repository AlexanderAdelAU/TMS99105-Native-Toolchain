The user reported the basic Ctrl-F candidate works on SBC hardware.

Agreed behavior
---------------
* Ctrl-F enters Find mode.
* Row 24 remains dedicated to "Find: <term>" while Find mode is active.
* Enter or Ctrl-F finds the next occurrence.
* After a successful match, the next search begins at match+1.
* This permits overlapping matches (e.g. AA in AAAA -> positions 0,1,2).
* The document view is redrawn around each match while Find remains active.
* Esc exits Find mode and restores the normal editor/status interface.
* Backspace/Delete edit the search term.
* Editing the term resets the starting point to the current document cursor.
* Search is case-sensitive, forward-only, non-wrapping, max 32 characters.
* Not found displays [Not found] on row 24 and leaves Find mode active.
* Find never modifies document bytes.

Implementation
--------------
Find remains wholly inside OVL_VIEW for the duration of the modal session.
The search pattern is local to vfind(); no new resident search buffer/state is
required.  The existing edflag=4 dispatch remains unchanged.
