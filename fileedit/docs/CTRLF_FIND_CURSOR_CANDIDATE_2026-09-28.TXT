SBC_FileEdit99_CTRLF_FIND_NEXT_candidate_2026-09-28
The user reported this Find-Next candidate works well on SBC hardware.

Change
------
After a successful Find, the logical editor cursor was already positioned at
match start, but the visible terminal cursor remained on the Find prompt while
Find mode waited for the next key.

This candidate keeps the Find prompt on row 24 but, after a successful match,
places the visible terminal cursor on the first character of the match before
waiting for Enter / Ctrl-F / Esc.

If the search pattern is edited with Backspace/Delete or printable input, the
visible cursor returns to the Find prompt. Esc exits Find mode with the editor
cursor still positioned at the match start.

Search semantics are unchanged:
* case-sensitive
* forward only
* no wrap-around
* Enter or Ctrl-F = find next
* next search starts at match+1
* overlapping matches remain supported
* Esc exits Find mode
