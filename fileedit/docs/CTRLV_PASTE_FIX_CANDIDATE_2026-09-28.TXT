FILEEDIT99 CTRL-V PASTE FIX CANDIDATE -- 2026-09-28
=======================================================

STATUS
------
Hardware candidate based on the hardware-validated Ctrl-F Find/Cursor build.
This supersedes the first Ctrl-V Paste candidate, which is REJECTED because
its footer exceeded column 79 and caused Tera Term to auto-wrap/scroll the
screen, corrupting the apparent line/status layout.

ROOT CAUSE OF DISPLAY REGRESSION
--------------------------------
The first Paste footer began at column 27 and was 56 characters long, ending
at column 82.  FILEEDIT deliberately leaves column 80 unused to prevent VT100
terminal auto-wrap.  The overflow wrapped onto the next terminal row and
scrolled the screen, producing duplicated/mangled Ln/Col status and an
apparently displaced cursor.

The corrected footer is exactly 53 characters and ends at column 79:
  Nav Home End PgUp/Dn ^F Find ^V Paste ^O Save ^X Menu

PASTE OPERATION
---------------
Ctrl-V on the SBC cannot read the Windows clipboard.  It arms FILEEDIT to
receive a terminal paste and displays:
  PASTE: use Edit>Paste, Esc finish

Then use Tera Term Edit -> Paste (or the terminal's configured Paste command)
to transmit clipboard text.  Press Esc after transmission completes.

Paste mode:
  - suppresses per-character redraw
  - accepts printable ASCII and TAB
  - normalizes CR, LF and CRLF to FILEEDIT internal CR newlines
  - uses the existing ebins() editor insertion path
  - performs one full redraw after Esc
  - leaves the editor cursor at the end of inserted text
  - reports receive-queue overrun instead of silently accepting lost bytes
