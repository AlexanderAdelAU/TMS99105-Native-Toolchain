SBC LINK99 - OVERLAY OWNERSHIP CONTRACT
=======================================

WHY THIS EXISTS
---------------
LINK99 uses OVLMGR to map the >8000-BFFF window. OVLMGR records the logical
window owner in CUR_WINA_ID when virtual segment 8 is mapped. This is a hard
architectural invariant, not a naming convention.

RULES
-----
1. OVLMGR_INIT must be called before any overlay or data-bank mapping.
   It explicitly clears CURRENT_PAGE[], CURRENT_ID[] and CUR_WINA_ID. No
   overlay owner may survive from an earlier program invocation.

2. Every callable/executable overlay must include virtual segment 8 in its
   mapping, and its first table pair must be the segment-8 pair. Mapping the
   executable overlay therefore establishes CUR_WINA_ID deterministically.

3. An overlay that does not own segment 8 is DATA ONLY. It may be used as a
   mapped workspace or storage bank, but it must never be entered with CALL,
   BL, B, or any other executable transfer.

4. Current LINK99 classifications (OVLMAP.TXT):

      ID 1       USAGE            Executable   segment 8, page 2
      IDs 2-11   CODE0..CODE9     Data         segment C, pages 2-11
      ID 12      SYM              Data         segments 9-B, pages 13-15
      ID 13      FINAL            Executable   segment 8, page 3
      ID 14      EXE              Executable   segment 8, page 4
      IDs 15-19  CODE10..CODE14   Data         segment C, pages 12-15, 1
      ID 20      MAP              Executable   segment 8, page 5
      ID 21      GLUE             Executable   segment 8, page 6
      ID 22      MAPM             Executable   segment 8, page 7
      ID 23      CHK              Executable   segment 8, page 8
      ID 24      TAB              Executable   segment 8, page 9

   The data banks are "guest" overlays and publish no entries, so nothing
   can call them; link99 fails the link if a guest maps segment 8.
   Segment D is never mapped: the shell keeps its internal commands on
   D pages 2-10.

5. When adding a new overlay, add it to OVLMAP.TXT.  link99 fails the link if
   a non-guest overlay does not map segment 8 first and exactly once, or if a
   guest maps it.  The build then checks every row against what this linker
   expects and checks that include\OVLDEFS.INC gives each overlay the ID
   link99 assigned (IDs follow first appearance in the map).

6. Do not bypass ovlinit/OVLMGR_INIT. Startup ownership is explicit by design.

REVIEW QUESTION
---------------
Before accepting any new mapped module ask:

    "Can execution enter this mapping? If yes, does it own segment 8, and has
     overlay state been explicitly initialized before the first mapping?"

If the answer is not unambiguously yes, the overlay design is invalid.
